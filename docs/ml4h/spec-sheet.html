1. Problem, users and setting

Primary care facilities across sub-Saharan Africa document in paper registers and compile the monthly return the ministry expects by hand. Connectivity is intermittent or absent, so tools that assume a server fail where the burden is highest. In Madagascar, where AfyaCore began, documentation is written in French while most patients speak Malagasy, so the instruction sheet a patient takes home is routinely in a language they cannot read. Phones are shared; records that leave the facility must be de-identified; and a speech tool that streams audio to a browser vendor discloses a patient's voice and diagnosis to a third party.

Users are nurses and clinicians at health posts, the administrator who configures the device, and the district office that receives DHIS2 aggregates. Nine country profiles ship (MG, SN, CI, CD, KE, NG, GH, TZ, UG), each a data entry: phone formats to redact, clinical language, HMIS, data-protection regime.

2. System

A progressive web app (React, TypeScript) installed from a URL on Android or iOS. IndexedDB is the source of truth, not a cache: every write succeeds locally and a facility offline for a week notices only a rising pending count. A zero-dependency Node sync server reconciles devices with cursor-based push-then-pull, enrolment by single-use code, server-side last-write-wins, and a rule that a local draft is never overwritten. Both sides keep a hash-chained audit log of who did what to which record id, never clinical content.

CaptureDictation, photo of a paper register, or typing. Whisper base (q8, ONNX, WebAssembly) in a worker; Tesseract on-device.
ExtractDeterministic clinical extractor driven by language packs (FR, EN): spoken numerals, cmHg convention, tds / 5/7 shorthand, fixed-dose combinations, plausibility ranges.
ReviewPer-field provenance and confidence; each machine value ticked individually against its source phrase; the record cannot become final otherwise, and an unconfirmed value is withheld from every export and aggregate.

3. Machine learning, and how it is kept safe

Three models run on the device, each an optional download the facility places on its own origin, none in the install: Whisper base (81 MB) for speech, Tesseract (7 MB) for print, and OpenMed French PII (70 MB, DistilBERT token classifier, Apache-2.0) for names the roster does not hold. An energy segmenter cuts the microphone at pauses and each utterance is transcribed as it closes, so results appear incrementally; known silence hallucinations are dropped. Text-to-fields is rules, on purpose: a 20% word error rate against free prose is unusable, but against eight vitals, a bounded formulary and a handful of frequency idioms it is very usable, because the output is a small set of fields a clinician confirms.

Five properties are structural rather than conventions. (1) Nothing machine-derived is saved without confirmation, field by field: a tick is bound to the exact value shown, a changed value is pending again, finaliseEncounter refuses a record with an unticked machine value, and because that guard only covers the draft-to-final moment, a value nobody has ticked is additionally withheld where the record leaves the device and where it becomes a statistic. (2) Extraction never overwrites typed input. (3) Every value carries its source, the phrase it came from, and an uncertainty flag that decides reading order rather than whether a value is reviewed. (4) Nothing is diagnostic: vital-sign colouring is a fixed threshold table, and the facility overview's excess rule is stated on screen as a prompt to look. (5) A confirmed record stays confirmed when corrected; the correction goes back through the same review gate. Drug names the recogniser spells phonetically are recovered by edit distance against the formulary only when a dose, frequency or duration follows, and always at a confidence that forces review with the raw phrase in view.

The speech rows are the honest centre of this sheet. The corpus is spoken by a text-to-speech voice, transcribed by the same model files through the same transformers.js build the phone runs, and scored by the same code as the text harness. The first run exposed regular failures: commas where full stops were spoken, so a diagnosis swallowed the prescription after it; par assez tamol for paracétamol; 5 stroke 7 for 5/7. Each is now handled and pinned by a test on the verbatim transcript. Synthetic speech is a controlled condition and not an upper bound: it removes noise, accent and disfluency, and adds a domain mismatch of its own. Recordings from intended users, independently annotated, are the next measurement and are not a substitute we can claim to have made.

Putting the recogniser in the loop also made the review interface measurable, which is where the last two rows come from. Every machine value is reviewed regardless, so the Check this flag only decides what a clinician reads first. But it was confidence < 0.8 and the extractor gives every chief complaint and diagnosis a confidence of exactly 0.8, so the two fields a recogniser mangles most could not be flagged at all, and they were the majority of every wrong value. Moving the line to the next boundary in the extractor's own scale, which has digit-derived vitals and complete prescriptions above it and spoken numerals, unit inferences, recovered drug names and narrative spans below it, takes a flag-first reviewer from 1 wrong value in 5 to nearly all of them. Both columns come from the corpus that found the problem: this is a correction, on 64 rows, not an independent validation.

The offline claim is tested in a real browser in CI: build, create an account, switch the network off, reload, sign in, record a consultation, reload again. Schema upgrades are tested against databases with data in them, including that a patient recorded before the consent field existed is treated as not having consented.

5. Deployment status and lessons learned

AfyaCore has not been validated with a facility, and no clinician has used it. Two rounds of finding out what it actually does shaped it more than any feature. An external review of v0.0.1 found five controls described more favourably than they behaved, among them dictation streaming audio to the browser vendor while the security document claimed no third-party call; each is fixed with a regression test named after the failure. Preparing this demonstration found a sixth: transformers.js 4.x requests an asyncify ONNX Runtime core the vendor scripts did not ship, so on-device inference had never started in a browser while every screen reported the model installed, because the availability probe checks for a config file rather than a working runtime. It was found by pressing the button; the bundled sample dictation exists so that pressing the button is part of every walk-through.

  • Measure the pipeline, not the parts. An extractor at 100% and a recogniser with published WER told us nothing about fields from speech until the two were scored together, and scoring them together is also what exposed the flag calibration and, indirectly, the export leak.
  • A guard placed at one transition does not cover the others. Requiring review before a draft becomes final read like a complete rule and was not: a correction is written into a record that is already final, so an unconfirmed diagnosis reached a research export and the district's malaria count. The fix withholds the field rather than demoting the record, because the consultation did happen.
  • Constants in a safety control need evidence too. A threshold nobody chose sat exactly on the confidence of the two fields it most needed to catch, and nothing failed: the interface simply looked confident about its worst answers.

6. Demonstration plan

A laptop and an Android phone serving the production build from a local origin with the models on it, synthetic data only. The laptop opens the app's evidence workspace, where an attendee picks a synthetic case, runs the vendored speech model on the device, and reads the transcript, the fields it produced, which match the reference, which the app had flagged, and how correcting the transcript changes the score, with a session record they can download. Then the clinical path on the phone: sign in on a shared device; dictate a consultation, or play the bundled sample when the hall is loud, and watch the transcript mark which words become which fields; tick each machine value and see the save refuse until the last is ticked; print the patient sheet in Malagasy; switch the network off, reload, continue; export the DHIS2 return and a pseudonymised FHIR bundle. Attendees can dictate in French or English themselves.

7. Limitations and ethics

Records are unencrypted at rest; device encryption protects them and a PIN only binds attribution. Eight of ten patient-sheet languages have not been read by a speaker and the sheet says so; wrong dosage wording is a safety issue. Malagasy dictation is excluded because Whisper produces confident French for Malagasy input. The audit chain detects tampering rather than preventing it. The facility overview is arithmetic, not epidemiology. Country legal metadata is not legal advice. The evaluation corpus was written alongside the implementation and bounds correctness on anticipated cases only.
